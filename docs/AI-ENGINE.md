# DDX Vision AI Engine (версия 5)

DDX Vision расширен из приложения «посмотреть загрузку» до **слоя интеллекта физического клуба**: камеры, данные клуба, оборудование и сессия участника превращаются в понимание состояния клуба, прогноз очередей, персональный маршрут и аналитику для управляющего.

Всё встроено в существующее приложение (`index.html`): дизайн, навигация, шкафчики, чат DDX AI, прогноз, режим тренировки и классический пульт работают как прежде.

## 1. Что работает по-настоящему, а что симулировано

| Часть | Статус |
|---|---|
| Движки: загрузка зон, прогноз +15/+30 мин, трафик и рекомендации, статусы оборудования, аномалии, отчёт дня | **Реальные алгоритмы** (`ai/core.js`). Вход — данные провайдеров |
| Vision Coach: счёт повторов, распознавание упражнения, диапазон / темп / симметрия, подсказки | **Реальный алгоритм** на ключевых точках (`ai/coach.js`). Позу сейчас выдаёт симулятор скелета |
| Динамический маршрут (перестановка, замена, возврат, усталость, ограничения, расстояние) | **Реальный алгоритм** (`ai/routing.js`), встроен в режим тренировки |
| Body Twin, Progress Engine, Return Engine | **Реальные расчёты** по истории (`ai/twin.js`). История и замеры — синтетические |
| Камеры, оборудование, браслеты/NFC, InBody, история тренировок | **Нет реальной интеграции.** Работает DEMO-режим, в интерфейсе везде метка DEMO |
| LIVE-режим | **Адаптеры написаны и проверены против мок-сервера**, но к настоящим сервисам DDX не подключались (нет доступа и ключей) |
| Языковая модель для пояснений | Не подключена. Есть интерфейс `ExplainerProvider` и защита «в тексте нет чисел вне фактов» |
| Шифрование, роли, журнал аудита | Интерфейс, журнал и права по зонам работают в демо; шифрование и вход выдаёт бэкенд DDX |

Соответствие законодательству не заявляется: оно требует отдельной юридической проверки.

## 2. Архитектура

```
CAMERAS → EDGE VISION (силуэты, зоны, ключевые точки; видео остаётся в клубе)
        → шина событий (только метаданные)
        → DDX VISION BACKEND
            Occupancy · Traffic · Equipment · Anomaly · Routing
            Vision Coach · Body Twin · Return · Prediction · Report
        → DDX AI ORCHESTRATOR (Orchestrator.update → снимок клуба)
        → API → DDX Vision (приложение, Command Center) · DDX Client App
```

Принцип: **PROCESS VIDEO — STORE DATA**. Базовый подсчёт людей не использует распознавание лиц: `Camera → Person Detection → Anonymous Tracking → Zone Mapping → Occupancy`. Персональная сессия Vision Coach создаётся только с согласия через браслет / NFC / QR / BLE; после упражнения связь закрывается.

### Провайдеры (ядро не привязано к производителю)

| Интерфейс | DEMO | LIVE (адаптер) |
|---|---|---|
| `CameraProvider` | `DemoCameraProvider` | `HttpCameraProvider` — `GET /v1/occupancy` |
| `EquipmentProvider` | `DemoEquipmentProvider` | `HttpEquipmentProvider` — `GET /v1/equipment` |
| `IdentityProvider` | `DemoIdentityProvider` (временные сессии) | `HttpIdentityProvider` (написан, в интерфейс пока не подключён) |
| `BodyCompositionProvider` | `DemoBodyCompositionProvider` | `HttpBodyCompositionProvider` (так же) |
| `WorkoutProvider` | `DemoWorkoutProvider` | `HttpWorkoutProvider` (так же) |
| `PoseProvider` | `SimulatedPoseProvider` | будет принимать поток ключевых точек с edge-сервера (`read(dt) → {t, kp3, kp2}`) |
| `ExplainerProvider` | `TemplateExplainer` | `LlmExplainer` (заглушка: нужен ключ и адрес) |

Если в LIVE-режиме источник не подключён, данные **не подменяются демо**: экран показывает «нет данных», а станция получает статус UNKNOWN.

## 3. Как это встроено в существующий код

- **`sw.js`** — кэш `ddx-vision-v5`, новые файлы в оболочке (работает без интернета).

## 4. Модели данных

**Уровни загрузки зоны:** `LOW` < 45% · `NORMAL` 45–70% · `BUSY` 70–95% · `CRITICAL` ≥ 95%.

**Зоны:** `free` Свободные веса · `legs` Ноги · `chest` Грудь · `back` Спина · `cardio` Кардио · `func` Функционал · `stretch` Растяжка · `group` Групповые · `locker` Раздевалки · `entrance` Вход.

**Снимок клуба** (`Orchestrator.update()`):

```js
{ ts, mode: 'DEMO'|'LIVE', clock:{dow,min}, clubCap, people, load,
  zones: [{ id, ru, count, capacity, p, level, dwell, p15, p30, level15, level30, trend, wait, wait15 }],
  eq: { items:[{ id,type,n,name,zone,status,etaMin,queue,slots,x,y }], counts, alerts },
  traffic: { predictions, recs:[{from,to,shift,savedMin,text,spare}], nextCritical:{zone,inMin}, auto, effect },
  activeEvents:[{ id,type,zone,sev,title,detail,dur }], peak:{min,load}, critical, kpis, report, summary }
```

**Статусы оборудования:** `AVAILABLE · IN_USE · QUEUE · OFFLINE · MAINTENANCE · UNKNOWN`.

**Ключевые точки Vision Coach:** набор COCO-17, `kp3` в метрах (x вбок, y вверх, z вперёд), `kp2` — проекция. Для упражнений заданы сигнал (угол) и пороги `sStart / sEffort`: приседание, выпад, жим плечами, сгибание на бицепс, разведение в стороны. Метрики повтора: `range` (GOOD / FAIR / SHALLOW), `tempo` (GOOD / FAST / SLOW, по времени возврата или спуска), `symmetry` (NORMAL / WATCH / UNEVEN). Неполный повтор не засчитывается.

**Return Engine:** сигнал `NORMAL | WATCH | DECLINING` по дням с последнего визита и изменению частоты (сравнение только при ≥ 8 визитов за прошлый период, чтобы не принимать обычный разброс за отток). Сотрудникам показываются сигнал, обезличенный номер и число дней — без диагнозов.

## 5. Контракты LIVE API

Авторизация: `Authorization: Bearer <токен>`. Токен хранится только в памяти страницы. Ответы — JSON; опрос раз в 2–3 секунды. Нужны CORS-заголовки для адреса приложения.

**`GET /v1/occupancy`**

```json
{ "clubId": "vat", "clubName": "Новые Ватутинки", "clubCap": 364, "people": 284,
  "zones": [ { "id": "free", "count": 31, "capacity": 33, "dwellMin": 18.2, "p": 0.94 } ],
  "entrance": { "in10": 42, "out10": 30 },
  "flows": [ { "from": "free", "to": "chest", "per10": 6 } ] }
```

`p` необязателен (иначе `count / capacity`). Не переданная зона показывается как «нет данных».

**`GET /v1/equipment`**

```json
{ "items": [ { "id": "chest1", "type": "chest", "n": 1, "name": "Жим от груди", "brand": "Technogym",
  "status": "QUEUE", "etaMin": 7, "queue": 1, "since": 12, "maxTypical": 11,
  "slots": null, "x": 118, "y": 265 } ] }
```

`type` — один из типов оборудования приложения (`rack`, `bench`, `chest`, `cross`, …); `x`, `y` — координаты станции на плане клуба (10 единиц ≈ 1 м) для расчёта расстояний в маршруте.

**Сессии и данные участника (адаптеры написаны, в интерфейс не подключены):**
`GET /v1/sessions/resolve?token=…` → `{ sessionId, ttlMin, consent }` · `GET /v1/members/{ref}/body-composition` · `GET /v1/members/{ref}/workouts?days=120`. Идентификатор `ref` — псевдоним, не имя.

**Поток позы (ещё не реализован в адаптере):** WebSocket `/v1/pose/stream?session=…`, кадры `{ t, kp3: [[x,y,z] × 17] }`, обработка на edge, видео не передаётся.

## 6. Приватность и безопасность

- видео не хранится: счётчик «0 Б видео» виден в сессии Vision Coach, сводка сессии содержит `bytesVideo: 0`;
- согласия: Vision Coach и каждый источник Body Twin включаются отдельно; отзыв сразу убирает показатели (вместо них INSUFFICIENT DATA);
- сроки хранения настраиваются (аналитика, ключевые точки, сессии), для видео фиксировано «не хранится»;
- камеры по зонам: в раздевалках и студии камер нет; просмотр камеры требует роли и записывается в журнал аудита; отказ тоже;
- роли: посетитель / тренер / управляющий (в демо переключаются вручную); Command Center и Return Engine закрыты для посетителя;
- удаление: кнопка «Удалить мои данные» сбрасывает согласия и локальные настройки (в продукте — запрос на бэкенд);
- AI не делает выводов о людях: аномалии описывают зону или станцию («нетипично высокая загрузка», «статус занято держится 42 мин»), решение принимает сотрудник.

## 9. Ограничения и следующие шаги

1. Подключить настоящий edge-сервис позы (MediaPipe / MoveNet) к `PoseProvider`; пороги и поправку темпа (`TEMPO_K`) подобрать на реальных записях.
2. Получить доступ к API камер и оборудования DDX и сверить контракты из раздела 5.
3. Провести юридическую проверку обработки данных и согласий.
4. Подключить языковую модель через `ExplainerProvider`, оставив проверку чисел.
5. Прогноз пока опирается на типовой день клуба; в LIVE его нужно обучать на накопленной истории камер и турникетов.
6. Отчёт дня в DEMO строится по модели дня; в LIVE нужен журнал событий на бэкенде.
